kubelet to api server: watch for work, report back

control plane Google runs it. You never reach a node directly.
  • api server
  • scheduler
  • controller manager
  • etcd

Two nginx Pods and two sky Pods, one of each per node, across two zones. Traffic only enters through the Gateway. The pink lines under the nodes are not traffic: that is each kubelet watching the control plane for work and reporting what it is running.

The new Pod has to pass its readiness probe before the old one starts its 35 second drain, so nothing lands on a Pod that is leaving. maxSurge 1, maxUnavailable 0, and a median of 70.5 s from merge to serving.

The HPA holds sky at 70% CPU and adds Pods up to 8. When the running nodes cannot fit them, the node autoscaler adds the third, which is its limit. Measured at 125 rps, p95 394 ms, no failures.

An upgrade cordons a node. The PodDisruptionBudget keeps at least one Pod of each app serving while the rest reschedule into the other zones, and the Service stops sending traffic to that node as soon as its endpoints go.

Cloud Armor allows 300 requests a minute from one address and answers 429 past that. The flood dies at the edge, before it costs a node anything, and nobody else's traffic changes.
